# ADR-011 – Slug-Generierung & Eindeutigkeit (V1)

Status: Accepted

---

## 1. Ziel

Definition eines deterministischen, kollisionsfreien Verfahrens zur Erzeugung
von Slugs für öffentlich adressierbare Ressourcen (Post, Category, Tag).

Diese ADR konkretisiert ADR-004, Kapitel 9 (Slug-Regelung).

---

## 2. Anwendungsbereich

Slugs werden erzeugt für:

```text
Post      → aus title
Category  → aus name
Tag       → aus name
```

Slugs sind Teil öffentlicher URLs (ADR-004) und werden nie als interne ID verwendet.

---

## 3. Normalisierungsregeln

Der Ausgangstext wird in folgenden Schritten normalisiert:

```text
1. Trim + Kleinschreibung
2. Umlaut-/Diakritika-Transliteration:
   ä→ae  ö→oe  ü→ue  ß→ss
   sonstige Diakritika via Unicode-NFD + Entfernung der Kombinationszeichen
   (é→e, ñ→n, ...)
3. Alle Zeichen außer [a-z0-9] → Bindestrich
4. Mehrfache Bindestriche → ein Bindestrich
5. Führende/abschließende Bindestriche entfernen
```

### Beispiele

```text
"Spring Boot für Anfänger!"   → spring-boot-fuer-anfaenger
"C# vs. Java"                 → c-vs-java
"   Hallo   Welt   "          → hallo-welt
```

---

## 4. Eindeutigkeit & Kollisionsauflösung

Slugs sind pro Ressourcentyp eindeutig (Unique-Constraint, ADR-010).

Bei Kollision wird ein numerisches Suffix angehängt:

```text
mein-post
mein-post-2
mein-post-3
```

### Algorithmus

```text
base = normalize(title)
candidate = base
n = 2
while slugExists(candidate):
    candidate = base + "-" + n
    n++
return candidate
```

Die Prüfung erfolgt gegen die jeweilige Tabelle. Der Unique-Constraint der
Datenbank bleibt die letzte Absicherung gegen Race Conditions.

---

## 5. Leerer Slug (Edge Case)

Ergibt die Normalisierung einen leeren String (z. B. Titel nur aus Emojis oder
Sonderzeichen), wird als Basis der Ressourcentyp plus ID-Fragment verwendet:

```text
"🚀🚀🚀"  → post-a1b2c3d4   (erste 8 Zeichen der UUID)
```

---

## 6. Änderungsverhalten

* Beim **Erstellen** wird der Slug automatisch aus dem Titel erzeugt
* Beim **Bearbeiten** bleibt ein bestehender Slug standardmäßig stabil
  (Permalink-Stabilität, SEO)
* Ein Slug kann optional explizit überschrieben werden (Admin-Feld);
  dann gelten Normalisierung und Kollisionsauflösung erneut
* Automatische Neu-Erzeugung bei Titeländerung ist **nicht** Standard

### Begründung Stabilität

Ein sich ändernder Slug bricht bestehende Links. Permalink-Stabilität hat
Vorrang vor Titel-Slug-Konsistenz.

---

## 7. Technische Verortung

* Zentrale `SlugService`-Komponente im Modul `common`
* Wird von `PostService`, `CategoryService`, `TagService` genutzt
* Keine Slug-Logik in Controllern oder Entitäten

---

## 8. Nicht Bestandteil V1

* Historie/Redirects alter Slugs (301-Redirect-Tabelle)
* Mehrsprachige Slugs
* Manuell konfigurierbare Transliterationstabellen
