# ADR-017 – Paketstruktur: Package by Feature (V1)

Status: Accepted

---

## 1. Ziel

Festlegung einer verbindlichen Paketstruktur für das Backend.
Ziel ist hohe Kohäsion innerhalb eines Features und geringe Kopplung zwischen Features.

---

## 2. Entscheidung: Package by Feature

Der Code wird **nicht** nach technischer Schicht organisiert
(`controller/`, `service/`, `repository/`),
sondern nach fachlichem Feature.

Jedes Feature ist ein eigenständiges Paket, das alle ihm zugehörigen Klassen enthält:
Entity, Repository, Service, Controller, DTOs.

---

## 4. Abhängigkeitsregeln

```text
common/      ← darf von allen Paketen genutzt werden
security/    ← darf von auth/ genutzt werden; kein Zugriff nach oben
config/      ← darf von allen genutzt werden
Features     ← dürfen aufeinander verweisen (z. B. post/ → user/, post/ → category/)
```

Ein Feature-Paket darf **niemals** von `common/` oder `security/` abhängen,
die ihrerseits von Features abhängen.

---

## 5. Entscheidungsbegründung

### Für Package by Feature

* Alle Klassen eines Features sind an einem Ort — kein Suchen über Schichtpakete
* Features können unabhängig voneinander entwickelt, getestet und reviewt werden
* Hohe Kohäsion: Was zusammengehört, liegt zusammen
* Konsistent mit der Open-Core-Strategie (ADR-006): Features sind klar abgrenzbar
* Einfaches Entfernen / Ersetzen eines Features ohne Seiteneffekte

### Gegen Package by Layer

* Bei wachsendem Projekt wird `service/`, `controller/` etc. unübersichtlich
* Keine klare fachliche Zuordnung auf Dateiebene erkennbar
* Schichttrennung ist durch Spring-Annotationen bereits ausgedrückt —
  die Paketstruktur muss sie nicht wiederholen

---

## 6. Controller-Benennung

Da Controller nicht mehr nach HTTP-Pfad-Segment benannt werden müssen,
gilt folgende Konvention:

```text
{Feature}PublicController    → /api/public/v1/{feature}
{Feature}AdminController     → /api/admin/v1/{feature}
AuthController               → /api/auth/*
```

---

## 7. DTOs

DTOs liegen im Unterpaket `{feature}/dto/` des jeweiligen Features.
Feature-übergreifende DTOs (z. B. `PageResponse`, `ErrorResponse`)
liegen in `common/`.

---

## 8. Nicht Bestandteil V1

* Modul-System (Maven-Module, JPMS)
* Hexagonale Architektur / Ports & Adapters
* Separate API-Module pro Feature
