# ADR-007 – Content/Presentation Separation

Status: Accepted

---

## 1. Ziel

Strikte architektonische Trennung von Inhalt und Darstellung –
als Grundlage für ein Theme-System ab Version 2.

Die eigentliche Entscheidung ist unmittelbar wirksam:
Das Backend liefert ausschließlich strukturierte Daten.
Wie diese dargestellt werden, ist vollständig Sache des Frontends.

---

## 2. Architekturprinzip

```text
Backend  →  strukturierte Daten (Markdown, JSON)
Frontend →  Darstellung (Themes, Komponenten, Layouts)
```

Content und Präsentation sind strikt voneinander getrennt.
Das Backend hat keine Kenntnis davon wie Inhalte gerendert werden.

---

## 3. Konsequenzen (sofort wirksam)

* Kein HTML wird im Backend gespeichert
* Markdown ist das einzige Content-Format (vgl. ADR-003)
* Alle öffentlichen APIs liefern ausschließlich rohe Inhaltsdaten
* Kein Layout-, Style- oder Theme-Wissen im Backend
* Theme-Wechsel erfordert keine Datenmigration

---

## 4. Zielarchitektur V2

```text
blog-cms/
├── backend/
├── admin-frontend/
└── themes/
    ├── default/
    ├── minimal/
    └── magazine/
```

Themes sind eigenständige Frontend-Pakete.
Sie konsumieren die Public API und sind austauschbar
ohne den Core zu berühren.

---

## 5. Begründung

* Markdown ist editor- und renderunabhängig
* Themes können unabhängig vom Backend versioniert werden
* Kein Vendor-Lock-in auf ein bestimmtes Frontend-Framework
* Konsistent mit der Open-Core-Strategie (ADR-006):
  Themes können open source oder kommerziell sein
* Saubere Separation of Concerns

---

## 6. Abgrenzung zum Admin-Frontend

Das Admin-Frontend ist kein Theme.
Es ist eine fest integrierte Verwaltungsoberfläche
und kein Teil des Theme-Systems.

---

## 7. Nicht Bestandteil V1

* Theme-System selbst
* Theme-Loader oder Theme-Registry
* Mehrere gleichzeitig installierte Themes
* Theme-Konfiguration über Admin-UI
