# ADR-006 – Open Core Strategy

Status: Accepted

---

## 1. Ziel

Das CMS wird als Open-Core-System entwickelt.

Der Core ist stabil, minimal und open source.
Zusätzliche Funktionen werden als eigenständige Plugins
oder Module implementiert – ohne den Core zu verändern.

---

## 2. Core

Der Core enthält ausschließlich grundlegende CMS-Funktionen:

```text
- Posts
- Kategorien
- Tags
- Medien
- Benutzer
- Authentifizierung
- REST API
```

---

## 3. Erweiterungen

Zusätzliche Funktionen werden als Plugins implementiert.

Beispiele:

```text
- Memberships
- Analytics
- Monetization
- Newsletter
- SEO Pro
```

Plugins sind nicht Bestandteil des Core-Repository.

---

## 4. Abhängigkeitsregel

```text
Core        →  darf niemals von Plugins abhängen
Plugins     →  dürfen auf Extension APIs des Core zugreifen
```

Diese Regel ist nicht verhandelbar.
Ein Core-Modul das ein Plugin importiert ist ein Architekturbruch.

---

## 5. Extension API (V1 Basis)

Als erster Extension Point wird das Spring Application Event System verwendet.

Plugins können auf Core-Ereignisse reagieren ohne den Core zu kennen:

```java
// Core wirft Event – kennt den Subscriber nicht
applicationEventPublisher.publishEvent(new PostPublishedEvent(post));

// Plugin reagiert – kennt den Core nur über das Event
@EventListener
public void onPostPublished(PostPublishedEvent event) { ... }
```

Definierte Core-Events in V1:

```text
PostPublishedEvent
PostArchivedEvent
UserCreatedEvent
```

Weitere Extension Points (z.B. Service-Interfaces, Hooks)
werden in späteren ADRs definiert sobald konkrete Plugin-Anforderungen bestehen.

---

## 6. Lizenzmodell

```text
Core     →  Open Source
Plugins  →  Open Source oder kommerziell möglich
```

Die Lizenz des Core schränkt die Lizenz von Plugins nicht ein.

---

## 7. Paketstruktur

Core-Module liegen unter:

```text
de.patrick.schmidt.blogcms.*
```

Plugins liegen außerhalb dieses Namespaces
und werden nicht in das Core-Repository eingecheckt.

---

## 8. Nicht Bestandteil V1

* Plugin-Loader oder Plugin-Registry
* Plugin-Marketplace
* Dynamisches Laden von Plugins zur Laufzeit
* Vollständige Extension API Spezifikation
