# ADR-015 – Fehler- & Validierungskatalog (V1)

Status: Accepted

---

## 1. Ziel

Vereinheitlichung der Fehlerbehandlung über das in ADR-004 definierte
Error-Format hinaus: ein zentrales Handling, ein maschinenlesbarer Fehlercode
und ein verbindlicher Validierungskatalog pro Ressource.

---

## 2. Erweitertes Fehlerformat

ADR-004 definiert das Basisformat. Es wird um `code` und `errors` erweitert:

```json
{
  "timestamp": "2026-06-09T12:00:00Z",
  "status": 400,
  "error": "Bad Request",
  "code": "VALIDATION_FAILED",
  "message": "Validation failed for 1 field(s)",
  "path": "/api/admin/v1/posts",
  "errors": [
    { "field": "title", "code": "NOT_BLANK", "message": "title must not be blank" }
  ]
}
```

* `code` – stabiler, maschinenlesbarer Fehlercode (UPPER_SNAKE_CASE)
* `errors` – nur bei Validierungsfehlern; sonst weggelassen
* `message` – menschenlesbar, nicht für Programmlogik gedacht

---

## 3. Zentrales Handling

* Ein globaler `@RestControllerAdvice` (`GlobalExceptionHandler`) im Modul `common`
* Kein `try/catch` für Fehler-Mapping in Controllern oder Services
* Domänenfehler werden als typisierte Exceptions geworfen und zentral gemappt

```text
ResourceNotFoundException   → 404 NOT_FOUND
ValidationException / Bean  → 400 VALIDATION_FAILED
InvalidStatusTransition     → 409 STATUS_TRANSITION_INVALID   (ADR-013)
DuplicateResourceException  → 409 DUPLICATE_RESOURCE
AuthenticationException     → 401 UNAUTHENTICATED
AccessDeniedException       → 403 FORBIDDEN
Unbehandelt                 → 500 INTERNAL_ERROR
```

---

## 4. HTTP-Status-Konventionen

```text
200 OK           erfolgreicher GET/PUT
201 Created      erfolgreicher POST (mit Location-Header)
204 No Content   erfolgreicher DELETE (Soft Delete, ADR-002)
400 Bad Request  Validierung / fehlerhafte Anfrage
401 Unauthorized fehlende/ungültige Authentifizierung
403 Forbidden    fehlende Berechtigung / Ownership (ADR-013)
404 Not Found    Ressource existiert nicht (oder nicht sichtbar)
409 Conflict     Eindeutigkeitsverletzung / ungültiger Statusübergang
500 Internal     unerwarteter Serverfehler
```

### 404 statt 403 bei fehlender Sichtbarkeit

Public-API-Zugriff auf nicht-`PUBLISHED`-Inhalte liefert `404`, nicht `403`
– die Existenz nicht-öffentlicher Inhalte wird nicht preisgegeben.

## 5. Fehlercode-Katalog (V1)

```text
VALIDATION_FAILED          400   Bean-Validation fehlgeschlagen
MALFORMED_REQUEST          400   nicht parsebarer Body / falscher Typ
UNAUTHENTICATED            401   kein/ungültiges Access Token
TOKEN_EXPIRED              401   Access Token abgelaufen
FORBIDDEN                  403   Rolle/Ownership unzureichend
NOT_FOUND                  404   Ressource nicht gefunden
DUPLICATE_RESOURCE         409   Unique-Verletzung (slug/username/email)
STATUS_TRANSITION_INVALID  409   unzulässiger Post-Statusübergang
PAYLOAD_TOO_LARGE          413   Datei überschreitet max-file-size (ADR-008)
UNSUPPORTED_MEDIA_TYPE     415   MIME-Type nicht erlaubt (ADR-008)
INTERNAL_ERROR             500   unerwarteter Fehler
```

---

## 6. Feld-Validierungskatalog

### Feld-Fehlercodes

```text
NOT_BLANK, NOT_NULL, SIZE, PATTERN, EMAIL, POSITIVE, ENUM_INVALID
```

### Post (PostRequest)

```text
title      NOT_BLANK, SIZE(1..200)
content    NOT_BLANK
excerpt    SIZE(0..500)
categoryId NOT_NULL bei gesetzter Kategorie – muss existieren
tagIds     jede ID muss existieren
status     ENUM_INVALID falls kein gültiger PostStatus
```

### Category / Tag

```text
name       NOT_BLANK, SIZE(1..100)
```

### User (UserRequest, ADR-004 Patch)

```text
username   NOT_BLANK, SIZE(3..50), PATTERN [a-zA-Z0-9_.-]
email      NOT_BLANK, EMAIL
password   NOT_BLANK, SIZE(min 8)        (nur bei Create/Reset)
role       ENUM_INVALID falls kein gültiger Role-Wert
```

### Media (ADR-008)

```text
file       NOT_NULL, MIME ∈ allowed-types, size ≤ max-file-size
```

---

## 7. Sicherheitsaspekte

* Fehlermeldungen enthalten **keine** Stacktraces oder internen Pfade in Prod
* Login-Fehler sind generisch („invalid credentials"), keine Unterscheidung
  zwischen falschem Username und falschem Passwort
* `500`-Antworten enthalten keine Exception-Details (nur `code` + generische Message)

---

## 8. Nicht Bestandteil V1

* Lokalisierte Fehlermeldungen (i18n)
* RFC 9457 Problem Details (`application/problem+json`)
* Fehler-Tracking-IDs / Correlation-IDs (später mit Logging-ADR)
