# ADR-003 – Domänenmodell & Post Lifecycle (V1)

Status: Accepted

---

## 1. Domänenmodell (V1)

Das System basiert auf folgenden Kern-Entitäten:

```text
User
Role
Post
Category
Tag
Media
```

---

## 2. Beziehungen

```text
User 1 ─── n Post

Post n ─── 1 Category

Post n ─── n Tag

Post 1 ─── n Media
```

---

## 3. Post Lifecycle (Statusmodell)

Posts durchlaufen einen definierten Lebenszyklus.

### Statusmodell:

```text
DRAFT → REVIEW → PUBLISHED → ARCHIVED
```

---

### Bedeutung der Status

#### DRAFT

* Beitrag ist in Bearbeitung
* nicht öffentlich sichtbar
* beliebig oft editierbar

#### REVIEW

* Beitrag ist fertiggestellt und wartet auf Freigabe
* optionaler Redaktionsstatus
* nicht öffentlich sichtbar

#### PUBLISHED

* Beitrag ist öffentlich verfügbar
* erscheint in API und Frontend
* Änderungen können neue Version erzeugen (später optional)

#### ARCHIVED

* Beitrag ist deaktiviert
* nicht mehr im Frontend sichtbar
* bleibt in Datenbank erhalten (kein Hard Delete)

---

## 4. Content-Modell

### Entscheidung: Markdown

Alle Post-Inhalte werden in Markdown gespeichert.

```text
content: Markdown String
```

---

### Begründung

* leicht lesbar und editierbar
* gut versionierbar (Git-kompatibel)
* einfach zu rendern (Backend oder Frontend)
* unabhängig vom Editor-Framework
* ideal für Open-Source-Projekte

---

## 5. Post-Datenstruktur (V1)

```text
Post
- id (UUID)
- title
- slug
- excerpt
- content (Markdown)
- status (DRAFT | REVIEW | PUBLISHED | ARCHIVED)
- author (User)
- category (Category)
- tags (List<Tag>)
- createdAt
- updatedAt
```

---

## 6. Erweiterbarkeit (Design-Ziel)

Das Modell ist bewusst so aufgebaut, dass später möglich ist:

* Versionierung von Posts
* Kommentare
* Mehrsprachigkeit
* SEO-Metadaten
* Plugin-System für Content-Blöcke

---

## 7. Nicht Bestandteil von V1

* Rich Text JSON Editor
* Kommentar-System
* Content-Version-History
* Workflow-Automatisierung
