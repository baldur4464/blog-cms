# ADR-005 – Authentication & Authorization (V1)

Status: Accepted

---

## 1. Ziel

Definition eines sicheren, skalierbaren Authentifizierungs- und Autorisierungssystems für das Blog-CMS.

Das System soll:

* Admin- und Autorenfunktionen absichern
* API-Zugriff kontrollieren
* zukunftssicher für externe Clients sein
* sauber in Spring Security integrierbar sein

---

## 2. Authentifizierungsverfahren

### Entscheidung: JWT-basiert

Es wird ein **stateless JWT Authentication System** verwendet.

### Token-Typen

```text id="token_types"
Access Token (kurzlebig)
Refresh Token (langlebig)
```

---

### Access Token

* Lebensdauer: ca. 15 Minuten
* Enthält:

  * userId (UUID)
  * username
  * roles
* Wird für API Requests genutzt

---

### Refresh Token

* Lebensdauer: ca. 7–30 Tage
* Wird zur Erneuerung von Access Tokens genutzt
* Wird serverseitig validiert und verwaltet

---

## 3. Token Storage

### Entscheidung: HttpOnly Cookies für Refresh Token

* Refresh Token wird in HttpOnly Cookie gespeichert
* Schutz vor XSS-Angriffen
* Access Token wird im Frontend gehalten (Memory)

---

## 4. Rollenmodell

```text id="roles"
ADMIN
EDITOR
AUTHOR
```

---

### Rollenbeschreibung

#### ADMIN

* Vollzugriff auf System
* Benutzerverwaltung
* Content-Management

#### EDITOR

* Kann alle Posts bearbeiten
* Kann Inhalte freigeben (REVIEW → PUBLISHED)

#### AUTHOR

* Kann eigene Posts erstellen und bearbeiten
* Kein Zugriff auf fremde Inhalte

---

## 5. API-Schutzmodell

### Public API

```text id="public_api_auth"
/api/public/v1/** → keine Auth erforderlich
```

---

### Admin API

```text id="admin_api_auth"
/api/admin/v1/** → JWT erforderlich
```

---

## 6. Spring Security Architektur

### Filter Chain

* JWT Authentication Filter
* Security Context Holder
* Role-based Authorization

---

### Beispiel Security Rule

```java id="security1"
http
    .authorizeHttpRequests(auth -> auth
        .requestMatchers("/api/public/**").permitAll()
        .requestMatchers("/api/admin/**").authenticated()
    )
```

---

## 7. Login Flow

### Endpoint

```http id="login"
POST /api/auth/login
```

### Ablauf

1. User sendet Credentials
2. System validiert Username/Password
3. JWT Access + Refresh Token werden erzeugt
4. Refresh Token wird als HttpOnly Cookie gesetzt
5. Access Token wird im Response Body zurückgegeben

---

## 8. Token Refresh Flow

```http id="refresh"
POST /api/auth/refresh
```

### Ablauf

1. Browser sendet Refresh Cookie
2. Server validiert Refresh Token
3. Neuer Access Token wird erzeugt
4. Optional: Refresh Token Rotation

---

## 9. Logout Flow

```http id="logout"
POST /api/auth/logout
```

* Refresh Token wird invalidiert
* Cookie wird gelöscht

---

## 10. Security Prinzipien

* Keine Passwörter im Klartext (BCrypt)
* JWT signiert (HMAC oder RSA optional später)
* Refresh Token Rotation empfohlen
* Rate Limiting (später optional)

---

## 11. Nicht Bestandteil V1

* OAuth Login (Google/GitHub)
* Multi-Factor Authentication
* API Keys für externe Systeme
* Session-based Auth

# ADR-005 – Patch: UI-Sprache je Benutzer (preferredLocale)

Status: Accepted (Ergänzung zu ADR-005)

---

## Änderung

Ergänzung zum Benutzermodell gemäß ADR-018 (Mehrsprachigkeit).

---

## User.preferredLocale

Das User-Entity erhält ein Feld **`preferredLocale`**
(`app_user.preferred_locale`, `VARCHAR(35)`, nullable) – die persönliche
**Oberflächensprache** (UI-Locale) des Benutzers.

* Betrifft ausschließlich die **Darstellung** (Admin-Panel, Fehler-/
  Validierungsmeldungen), **nicht** die Inhaltssprache (ADR-018 Kapitel 3).
* Wird nach dem Login als UI-Sprache angewandt und in die Locale-Verhandlung
  eingereiht (ADR-018 Kapitel 8).
* `NULL` ⇒ Fallback über `Accept-Language` → `default-locale`.
* Nur Werte aus `app.i18n.supported-locales` sind zulässig.

---

## Endpoint

### Eigene UI-Sprache setzen

```http
PUT /api/admin/v1/users/me/preferred-locale
```

```json
{ "preferredLocale": "en" }
```

* Jeder authentifizierte Benutzer darf **nur die eigene** Präferenz setzen.
* `preferredLocale` wird zusätzlich in die User-Response (ADR-004 Patch)
  aufgenommen.

---
