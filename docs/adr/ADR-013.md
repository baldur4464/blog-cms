# ADR-013 – Post-Status-Übergänge & Berechtigungen (V1)

Status: Accepted

---

## 1. Ziel

Präzisierung des in ADR-003 definierten Post-Lifecycles zu einer verbindlichen
Zustandsmaschine: welche Übergänge erlaubt sind und welche Rolle (ADR-005) sie
auslösen darf.

---

## 2. Zustände (aus ADR-003)

```text
DRAFT → REVIEW → PUBLISHED → ARCHIVED
```

Ergänzt um explizit erlaubte Rückübergänge (siehe Kapitel 3).

---

## 3. Erlaubte Übergänge

```text
DRAFT      → REVIEW        (zur Freigabe einreichen)
DRAFT      → PUBLISHED     (direkt veröffentlichen)
REVIEW     → PUBLISHED     (freigeben)
REVIEW     → DRAFT         (zurückweisen / zurückziehen)
PUBLISHED  → ARCHIVED      (deaktivieren)
PUBLISHED  → DRAFT         (depublizieren zur Überarbeitung)
ARCHIVED   → DRAFT         (reaktivieren zur Überarbeitung)
```

### Nicht erlaubt

```text
ARCHIVED   → PUBLISHED     (kein direktes Reaktivieren; Weg über DRAFT)
*          → gleicher Status (No-Op wird als 409 abgelehnt)
beliebige nicht gelistete Übergänge
```

Ein nicht erlaubter Übergang führt zu `409 Conflict` mit einem
Fehlercode aus ADR-015.

---

## 4. Berechtigungen pro Übergang

Rollen gemäß ADR-005: `ADMIN`, `EDITOR`, `AUTHOR`.

```text
Übergang                Erlaubte Rollen
------------------------------------------------
DRAFT    → REVIEW        AUTHOR (eigene), EDITOR, ADMIN
DRAFT    → PUBLISHED     EDITOR, ADMIN
REVIEW   → PUBLISHED     EDITOR, ADMIN
REVIEW   → DRAFT         EDITOR, ADMIN
PUBLISHED→ ARCHIVED      EDITOR, ADMIN
PUBLISHED→ DRAFT         EDITOR, ADMIN
ARCHIVED → DRAFT         EDITOR, ADMIN
```

### Kernregel

* **AUTHOR** darf ausschließlich **eigene** Posts bearbeiten und sie maximal bis
  `REVIEW` bringen. Veröffentlichung ist AUTHOR nicht gestattet.
* **EDITOR** darf alle Posts bearbeiten und alle Übergänge auslösen.
* **ADMIN** hat Vollzugriff.

Dies ist konsistent mit den Rollenbeschreibungen in ADR-005.

---

## 5. Eigentümerschaft (Ownership)

* AUTHOR-Zugriff wird gegen `post.author == currentUser` geprüft
* Verstoß → `403 Forbidden`
* EDITOR/ADMIN sind von der Ownership-Prüfung ausgenommen

---

## 6. Veröffentlichungs-Zeitpunkt

* Beim ersten Übergang **nach** `PUBLISHED` wird `publishedAt` gesetzt
  (falls noch nicht vorhanden)
* `publishedAt` wird bei erneutem Publish **nicht** überschrieben
* Sortierung/Filter der Public API (ADR-004) nutzen `publishedAt`

> Hinweis: `publishedAt` ergänzt die Post-Datenstruktur aus ADR-003 und wird in
> das Schema (ADR-010) aufgenommen.

---

## 7. Sichtbarkeit (Konsistenz mit ADR-002 / ADR-004)

```text
Public API   →  liefert ausschließlich Status = PUBLISHED
Admin API    →  liefert alle Status (Filter optional)
```

---

## 8. Technische Verortung

* Übergangsregeln zentral in `PostStatusTransition` (Modul `post`)
* Prüfung im `PostService` vor dem Persistieren
* `PostPublishedEvent` / `PostArchivedEvent` (ADR-006) werden **nach**
  erfolgreichem Übergang publiziert

---

## 9. Nicht Bestandteil V1

* Geplante/zeitgesteuerte Veröffentlichung (Scheduling)
* Redaktioneller Kommentar-Workflow bei Rückweisung
* Mehrstufige Freigabeketten
* Versionierung bei Depublizierung
